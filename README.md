# Erseli PWA — إرسلي

واجهة أولية لمنصة توصيل محلية في الجزائر، مبنية باستخدام React + TypeScript + Vite، ومهيأة كتطبيق PWA.

## الموجود في هذه النسخة

- واجهة عربية RTL متجاوبة مع الهاتف والكمبيوتر.
- صفحات رئيسية وخدمات: الطعام، الطرود، المشتريات، الأعمال.
- طلب على الخريطة (نقطة انطلاق/وصول، اقتراح سعر، طلب كضيف أو بحساب).
- صفحة «طلباتي»: كل طلب مع حالته، شريط مراحل التوصيل، وإلغاء الطلب قبل الاستلام.
- **تأكيد تسليم من الطرفين**: الموصّل يؤكد التسليم، والزبون يؤكد الاستلام، ولا يكتمل الطلب إلا بالتأكيدين.
- **تقييم الموصّل** بالنجوم بعد اكتمال الاستلام، مع متوسط التقييم في ملفه.
- **تفاوض على السعر**: الزبون يرى عروض الموصّلين ويقبل عرضًا واحدًا فيُسند الطلب ويُثبَّت السعر.
- **دردشة كتابية** لكل طلب بين الزبون والموصّل المسند فقط.
- **إشعارات لكل الموظفين** عند وصول طلب جديد، مع جرس وصندوق إشعارات داخل التطبيق.
- **ملف شخصي** لكل حساب مع صورة قابلة للتغيير، و**لوحة أسبوعية** لكل موظف (ناجحة / قيد التنفيذ / الدخل).
- لوحة عمل الموصّل: استلام الطلبات، تقدّم الحالة، وزر «متاح للعمل».
- لوحة إدارة كاملة (جلسة + دور admin).
- **لوحة قراءة بالرمز**: الطلبات الجارية/المكتملة/الملغاة والحسابات والإحصائيات بدون تسجيل دخول، قراءة فقط.
- ملف PWA وService Worker وأيقونة.
- كود SQL موحّد في ملف واحد لـ Supabase، مع سياسات RLS واختبارات سلوك.

## تنبيه مهم

هذه **نسخة قابلة للتشغيل والاختبار وليست منصة إنتاج مكتملة**. الدفع، الإشعارات، التتبع الحي للموصّل، والرسائل النصية تحتاج مزوّدين وإعدادًا خارجيًا. لوحة الإدارة الكاملة تتطلب جلسة بدور `admin` من قاعدة البيانات، ولوحة القراءة بالرمز لا تغيّر أي دور لكنها تعرض أرقام هواتف الزبائن: اعتبر الرمز سرًّا وغيِّره عن القيمة الافتراضية قبل أي استخدام حقيقي.

تفاصيل طبقة الطلبات الجديدة (تسليم ثنائي، تقييم، دردشة، إشعارات، ملفات، إحصائيات) في **[FEATURES_SOCIAL.md](FEATURES_SOCIAL.md)** — وفيه قائمة الإعدادات الخارجية المطلوبة ونتائج الاختبارات.

## المتطلبات

- Node.js 20 أو أحدث
- حساب Supabase لإنشاء قاعدة البيانات والمصادقة
- محرر مثل VS Code

## التشغيل محليًا

```bash
npm install
cp .env.example .env.local
npm run dev
```

افتح عنوان Vite الذي يظهر في الطرفية. إذا لم تُضف مفاتيح Supabase تبقى الصفحات العامة قابلة للعرض، لكن أي محاولة لإنشاء حساب أو حفظ طلب ستُظهر رسالة بأن الخدمة غير مُهيّأة. لا تُعرض أي لافتة تقنية للزائر؛ التنبيه يظهر في طرفية المتصفح (Console) لمن ينشر التطبيق.

## إعداد Supabase

1. أنشئ مشروعًا جديدًا في Supabase.
2. افتح SQL Editor والصق **ملف واحد**: `supabase/ersel_all_in_one.sql` ثم Run.
   هذا الملف يجمع كل الهجرات والمقترحات المعتمدة بالترتيب، ويُنشئ قاعدة كاملة من
   الصفر، وآمن للتشغيل أكثر من مرة.
3. انسخ Project URL وanon/public key إلى `.env.local`.
4. أعد تشغيل `npm run dev`.

للتحقق قبل التشغيل (بدون أي مفاتيح، على PostgreSQL مصغّر داخل Node):

```bash
npm run test:sql     # ينفّذ الملف مرتين + 36 اختبار سلوك (أدوار، RLS، سلسلة الحالة، اللوحة بالرمز)
```

بعد تعديل أي ملف SQL مفرد، أعد بناء الملف الموحّد:

```bash
npm run sql:build
```

### إذا فشل التشغيل على قاعدة موجودة مسبقًا

| الخطأ | السبب | الحل |
|---|---|---|
| `operator does not exist: text = order_status` | جداول أُنشئت بنسخة أقدم جعلت `orders.status` من نوع `text`، و`create table if not exists` يتجاوزها | أعد تشغيل الملف: القسم 01 يحوّل الأعمدة النصية إلى أنواعها تلقائيًا قبل أي مقارنة |
| `legacy_value_not_in_enum: … (قيمة)` | صف يحمل حالة غير معروفة | صحّح القيم المذكورة ثم أعد التشغيل |
| `check constraint "orders_min_price" … violated` | طلبات قديمة بسعر أقل من 100 دج | لم يعد يوقف التشغيل: القيد يُضاف `not valid` ويطبق على الطلبات الجديدة |

للبدء من الصفر بلا بيانات (يحذف كل جداول `public` — لا تفعله إن كان لديك بيانات حقيقية):

```sql
drop schema public cascade;
create schema public;
grant usage on schema public to anon, authenticated, service_role;
```

لا تضع `service_role` key داخل تطبيق المتصفح أبدًا. استخدم anon key فقط في الواجهة مع سياسات RLS صحيحة.

## لوحة القراءة بالرمز (للمالك من الهاتف)

اللوحة الكاملة تحتاج حسابًا بدور `admin`. أما الاطلاع السريع على الطلبات والحسابات فيتم برمز فقط:

1. **غيّر الرمز الافتراضي أولًا** من SQL Editor (الرمز الافتراضي `101112` مرفوض في هذه اللوحة):

   ```sql
   select public.set_admin_code('ERSEL-2026-ADMIN');
   ```

   الحد الأدنى 10 محارف. يُخزَّن كـ bcrypt hash في `public.admin_secret`، ولا يُعاد أبدًا.

2. **افتح اللوحة**: اضغط شعار ERSEL أربع مرات متتالية (أو اضغط «لديك رمز إدارة؟» في شاشة الدخول) ثم أدخل الرمز واضغط «عرض الطلبات والحسابات بالرمز».

3. ما تعرضه اللوحة (قراءة فقط، بلا أي كتابة):
   - تبويبات: **قيد التنفيذ** (pending/accepted/picked_up/in_transit)، **مكتملة**، **ملغاة**.
   - بحث برقم الطلب أو الاسم أو الهاتف أو العنوان، مع اتصال مباشر ونسخ الرقم.
   - تبويب **الحسابات**: الدور، الهاتف، تاريخ التسجيل، وحالة توثيق/توفّر الموصّل.
   - إحصائيات: الجارية، المكتملة، الملغاة، الزبائن، الموصّلون (الموثّقون والمتاحون)، الموظفون، المدراء.

4. حدود يجب معرفتها:
   - الدالة `admin_code_view` لا تغيّر أي دور ولا تكتب أي بيانات.
   - المحاولات محدودة عالميًا: 20 محاولة فاشلة كل 15 دقيقة.
   - تعرض أحدث 120 طلبًا و200 حساب.
   - الرمز يبقى في ذاكرة الصفحة فقط؛ لا يُحفظ في `localStorage` ولا في الرابط.
   - من يعرف الرمز يرى أرقام هواتف الزبائن — لا تشارك الشاشة أو صورها.

## بناء نسخة النشر

```bash
npm run build
npm run preview
```

انشر مجلد `dist` على استضافة HTTPS تدعم تطبيقات SPA. ملف `public/sw.js` يُنسخ إلى `dist/sw.js` عبر Vite. اختبر التثبيت على Android وiOS بعد النشر عبر HTTPS.

## خطة الوصول إلى MVP قابل للاستخدام

### المرحلة 1 — أساس المنتج
- اختيار مدينة الإطلاق ومنطقة الخدمة.
- تأكيد الاسم التجاري والنطاق.
- اعتماد قائمة الخدمات والسلع الممنوعة أو التي تتطلب شروطًا خاصة.
- تحديد نموذج التسعير والعمولة وسياسة الإلغاء.

### المرحلة 2 — الحسابات والصلاحيات
- Supabase Auth: زبون، موصّل، مدير.
- إنشاء الملف الشخصي تلقائيًا عبر trigger موثوق.
- جعل تغيير الدور والتحقق من الموصّل من صلاحيات الإدارة فقط.
- حماية كل البيانات باستخدام RLS واختبارات وصول.

### المرحلة 3 — دورة الطلب
- إنشاء الطلب من حساب مسجل.
- تقدير السعر حسب المدينة والمسافة ونوع المركبة والخدمة.
- قائمة طلبات متاحة للموصّلين المؤهلين.
- قبول ذري للطلب لتفادي قبول سائقين اثنين له.
- حالات الطلب مع سجل تغييرات وتأكيد التسليم.

### المرحلة 4 — الخرائط والإشعارات
- مزود خرائط مع تغطية مناسبة للمدينة المختارة.
- تحديد العناوين والإحداثيات وحساب المسافة.
- إشعارات PWA؛ دعم iOS يعتمد على إصدار النظام وطريقة تثبيت التطبيق.
- لا تعتمد على الموقع في الخلفية على أنه مضمون في PWA.

### المرحلة 5 — الإدارة والعمليات
- إدارة الموصّلين والوثائق والتحقق.
- إدارة الطلبات والأسعار والعمولات ومناطق الخدمة.
- معالجة الشكاوى والاستردادات ومراجعة التسليم.
- سجل تدقيق لكل تغيير إداري.

### المرحلة 6 — الاختبار والإطلاق
- اختبارات أمن RLS وحالات الطلب المتزامنة.
- اختبار على أجهزة iPhone وAndroid واتصال ضعيف.
- سياسة خصوصية وشروط استخدام ودعم العملاء.
- مراجعة قانونية محلية للأنشطة والتأمين والضرائب ومعالجة البيانات.
- إطلاق تجريبي في منطقة صغيرة مع عدد محدود من الموصّلين.

## ملاحظات المنتج

- ابدأ بالدفع النقدي عند التسليم إن كان مناسبًا قانونيًا وتشغيليًا، وأضف الدفع الإلكتروني بعد التحقق من مزود محلي.
- لا تجمع صور الهوية أو رخص القيادة قبل إعداد تخزين خاص، صلاحيات محددة، سياسة احتفاظ، وإجراء حذف آمن.
- لا تفعّل نشر لوحة الإدارة قبل إضافة مصادقة وتحقق من الدور في قاعدة البيانات.
- احسب التكاليف التشغيلية: الخرائط، الرسائل النصية، الاستضافة، الدعم، التأمين والتسويق.

## تطبيق أندرويد وملف APK

**لا Android Studio ولا Java.** GitHub يبني الـ APK من ملف واحد:
`.github/workflows/build-apk.yml`. الدليل الكامل: **[ANDROID.md](ANDROID.md)**.

المستودع **لا يحتوي `android/`**: المجلد يُولَّد داخل التشغيل بـ
`scripts/android-init.mjs` (Capacitor + `android-overlay/` + الأيقونة + الصوت)،
فيبقى ما ترفعه 106 ملفًا فقط.

الطريق المختصر:

1. **Add file ← Upload files** — ارفع المشروع على دفعتين (انظر ANDROID.md §1).
2. **Add file ← Create new file** ← `.github/workflows/build-apk.yml` — الصق الملف.
3. Settings ← Variables: `VITE_SUPABASE_URL` و`VITE_SUPABASE_ANON_KEY`.
4. كل push يبني تلقائيًا (**Actions ← Build APK**) وينشر `ersel.apk` في
   **Releases** — بعد ~6 دقائق من أول commit.
5. الرابط ثابت ولا يتغيّر:
   `https://github.com/<USER>/<REPO>/releases/latest/download/ersel.apk`
   ويُحقن تلقائيًا داخل زر «تحميل APK» في الموقع.

ما يظهر للمستخدم: زر في الشريط العلوي وعلى الرئيسية، **على أجهزة أندرويد فقط**،
يفتح لوحة تثبيت فيها التحميل وخطوات التثبيت ومفتاح الإشعارات و«إضافة إلى الشاشة
الرئيسية». الإشعارات تعمل بصوت مخصّص (`res/raw/ersel_chime.wav`) على قناة
`ersel_orders`.

بناء محلي (يحتاج JDK 21 + Android SDK):

```bash
npm install
npm run android:init   # يولّد android/ + الأيقونة + الصوت
npm run android:apk    # android/app/build/outputs/apk/release/
```
